# Reflection

The thing I copied the most was the header nav and footer block. Every single page has the same chunk of HTML with the logo the site title and four links. I pasted it alot of times and every time I had to stop and do the paths. Root pages use styles/site.css and images/logo.svg but anything inside guide/ needs ../ in front or stuff just breaks silent. When I was moving files around the guide folder gave me the most trouble. I kept forgetting which links needed ../ and which ones didn't. The stylesheet paths was different from the nav hrefs and I mixed them up a couple times. The logo would show up fine but a nav link would 404 or the CSS would just not load and the page looked totally unstyled. Relative paths make sense in theory but when you are hand editing nine files it is easy to miss one. If I had a tool I would want it to generate the shared skeleton for me first. Header nav footer with the right path prefix based on how deep the page is. That alone would of saved me the most time. I would also want it to mark the current page in the nav automatically instead of me typing aria-current on each file by hand. The layout CSS files can stay separate since each page uses a different technique but the form on join and the cheese guide content could also come from a template. Basically anything that is identical or almost identical across pages should not be something I copy paste. Doing it once by hand was useful because now I get why people use components and static site generators but I would not want to do this for a real site with fifty pages. Next time I would rather write the content once and let something else figure out the paths.
