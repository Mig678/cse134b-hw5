# CSE 134B HW5 — Portfolio Site

This portfolio began as hand-maintained HTML from HW2 and was converted into a site generated by [Eleventy](https://www.11ty.dev/) (11ty). The deployed site adds two JavaScript layers on top of the HTML-and-CSS baseline: a theme picker (Part 1) and a network-backed `<recent-earthquakes>` custom element (Part 2).

- **Deployed site:** https://miguel-cse134b-hw5.netlify.app/
- **Repository:** https://github.com/Mig678/cse134b-hw5

## Local Setup

Install dependencies, run the development server, or build the static output:

```bash
npm install
npm run dev
npm run build
```

- `npm run dev` starts Eleventy with live reload (`eleventy --serve`).
- `npm start` is an alias for `npm run dev`.
- `npm run build` writes the generated site to `_site/`.

Requirements: Node.js with npm. The project uses `@11ty/eleventy` as a development dependency.

## Part 1: Theme Picker (Option A)

**Chosen option:** Theme picker (not contact-form validation).

### No-JavaScript baseline

Without JavaScript, the site remains fully usable. Styling comes from `src/css/site.css`, which defines:

- CSS custom properties for light and dark colors
- `color-scheme: light dark` on `:root`
- Automatic dark styling through `@media (prefers-color-scheme: dark)`
- Explicit overrides through `html[data-theme="light"]` and `html[data-theme="dark"]`

No theme control appears in the HTML when JavaScript is disabled. The picker is created only by script, so there is no dead or misleading control.

### Enhancement behavior

`js/theme-picker.js` is loaded site-wide from `src/_includes/layouts/base.njk` as `type="module"`. It:

1. Reads the saved preference from `localStorage` (key: `theme-preference`) inside try/catch blocks
2. Applies the theme immediately by setting or removing `data-theme` on `<html>`
3. Inserts a labeled `<select>` into the site header with **System**, **Light**, and **Dark**
4. Persists the user’s choice on change

| Selection | Effect on `<html>` |
|-----------|-------------------|
| System | Removes `data-theme` (follows `prefers-color-scheme`) |
| Light | Sets `data-theme="light"` |
| Dark | Sets `data-theme="dark"` |

Invalid stored values are ignored and fall back to **System**. If `localStorage` is unavailable, the page still works using the system theme; the choice simply is not persisted.

The control is built with DOM APIs and `textContent` only (no `innerHTML`, no inline event-handler attributes).

### Theme flash

The module calls `applyTheme()` as soon as it runs, before creating the visible control. That restores a saved light or dark preference quickly on each page load.

**Limitation:** Because the script is an external ES module, it runs after HTML parsing. The first paint may briefly show the system theme before a stored override is applied. Avoiding that completely would require a synchronous blocking script in `<head>`, which this assignment setup does not use.

## Part 2: `<recent-earthquakes>` Web Component

### Reference

| Item | Value |
|------|-------|
| **Tag name** | `recent-earthquakes` |
| **Script** | `js/recent-earthquakes.js` (loaded on the homepage only) |
| **Endpoint** | `https://earthquake.usgs.gov/earthquakes/feed/v1.0/summary/all_day.geojson` |
| **API key** | None (keyless public USGS feed) |

#### Attribute: `count`

| | |
|-|-|
| **Default** | `5` (when the attribute is omitted) |
| **Accepted values** | Integers from `1` through `10` |
| **Invalid values** | Fall back to `5` |

Changing `count` in DevTools after the component is connected re-slices the current or cached feed and updates the visible list without an unnecessary refetch when valid cached data is available.

#### States

The element reflects status with `data-state`:

- `idle` — before or without usable results
- `loading` — fetch in progress (status text with `aria-live="polite"`)
- `ready` — semantic ordered list of earthquakes
- `error` — readable error message and a keyboard-operable **Retry** button

#### Usage example

```html
<recent-earthquakes count="5">
  <p>
    Live earthquake data is loaded with JavaScript from the
    U.S. Geological Survey.
  </p>
  <p>
    <a href="https://earthquake.usgs.gov/">Visit the USGS earthquake site</a>
    for current information when JavaScript is unavailable.
  </p>
</recent-earthquakes>
```

On the generated homepage (`src/index.njk`), fallback content remains visible until the component reaches the `ready` state.

### Lifecycle and requests

- Registered with `customElements.define`
- `connectedCallback` sets up the UI and loads data
- `disconnectedCallback` cancels in-flight work
- `static observedAttributes = ["count"]` with `attributeChangedCallback`
- Fetches use `AbortController` and an **8-second** timeout
- Successful responses are cached in `sessionStorage` for **5 minutes** (key: `recent-earthquakes-usgs-all-day`), with try/catch around storage access

### Safe rendering

Static markup comes from a `<template>` built in JavaScript. USGS field values (magnitude, place, time, URLs) are inserted with `textContent`, safe attribute assignment, and DOM node creation — never by concatenating remote data into `innerHTML`.

**Why this matters:** If remote JSON were assigned through `innerHTML`, unexpected or malicious strings in the feed could inject markup or scripts. Using `textContent` and explicit DOM construction treats API data as plain text.

Each list item includes magnitude, place, a formatted local time, and—when the URL is a safe `https:` link—a link labeled as an official USGS event page. Attribution to the U.S. Geological Survey appears inside the component.

## Part 3: Eleventy Static Site Generation

**SSG chosen:** Eleventy 3.x

### Source structure

| Path | Purpose |
|------|---------|
| `src/_data/site.json` | Global site title, author, year, base URL, navigation, social links, sitemap paths |
| `src/_includes/layouts/base.njk` | Document shell, skip link, main slot |
| `src/_includes/layouts/project.njk` | Shared template for project detail pages |
| `src/_includes/partials/head.njk` | Charset, viewport, title, meta description, favicon, stylesheet |
| `src/_includes/partials/header.njk` | Logo, page heading, navigation |
| `src/_includes/partials/footer.njk` | Copyright and social links |
| `src/index.njk`, `src/about.njk`, etc. | Page content with front matter |
| `src/projects/*.md` | Three résumé projects in one tagged collection |
| `src/projects.njk` | Projects listing (loops `collections.projects`) |
| `src/404.njk` | Generated `/404.html` |
| `src/sitemap.xml.njk` | Generated `/sitemap.xml` |
| `src/css/site.css` | Site styles (passthrough copied to `_site/css/`) |
| `eleventy.config.js` | Input/output directories, passthrough copy, projects collection |

Navigation marks the current page at build time with `aria-current="page"` using each page’s `navKey` and the shared nav data in `site.json`. The `<footer>` element appears in one source file: `src/_includes/partials/footer.njk`.

Three project pages are generated from one template (`project.njk`) and front matter in:

- `src/projects/piyali-language-learning-app.md`
- `src/projects/dynamic-memory-allocator.md`
- `src/projects/shadoweval-llm-rollout-regression-platform.md`

### Deployment

Netlify builds from source using `netlify.toml`:

- **Build command:** `npm run build`
- **Publish directory:** `_site`

The public URL is recorded in `deployed-url.json` at the repository root. The same base URL (without a trailing slash) is stored in `site.json` for sitemap generation.

### SSG reflection

**What the conversion removed:** Repeated `<head>`, header, navigation, and footer markup that was copied across every HW2 HTML file. Project detail pages no longer exist as three nearly identical hand-edited files.

**What it cost:** A build step, Eleventy configuration, template syntax, and thinking in terms of layouts, data, and collections before content appears in `_site/`.

**What I would not use an SSG for:** A single page or a highly dynamic app where content changes per request. For a small, mostly static portfolio with shared chrome and data-driven project pages, the duplication removed outweighs the setup overhead.
